# 구매대행 과정 조사와 두 가지 도구 구현 — 윤장한

## 검증하고자 한 내용

개인이 에이전트의 도움을 받아 상품 조사·주문·배송신청을 어디까지 진행할 수 있는지, 상품 URL의 정보로 배송·관세 비용을 어느 범위까지 추정할 수 있는지 확인하고자 했습니다.

## 과정에서 확인한 내용

경로별 비용을 비교하려면 상품값 외에 운임·취급료·포장·특전 조건을 확인해야 했습니다. 실제 구매에는 로그인·추가 인증이 필요했고, 주문·배송신청 정보를 입력한 뒤 접수 결과를 다시 확인해야 했습니다. 상품 페이지에 포장 사양과 분류 정보가 부족한 경우도 있었습니다.

## 어려움과 생각

메루카리는 해외 거주자로 직접 가입·구매하는 데 어려움이 있었고, tenso의 주소 증빙 보완 과정도 까다롭게 느껴졌습니다. 이번 실구매는 라쿠텐·몰테일 경로로 진행했습니다.

소형 상품의 단품 배송비가 부담스럽게 느껴져 합배송으로 개당 비용을 줄일 수 있을지 생각했습니다. 합친 무게·부피와 추가 수수료까지 비교해야 하므로 아직 검증되지 않은 가설로 남겼습니다.

## 만들어본 도구

- **Codex 플러그인:** 상품 조사와 견적 비교, 라쿠텐 주문 대조, 몰테일 신청을 보조합니다. 다섯 개 skill과 Python·SQLite helper로 구성했습니다. 배송 추적 메일 확인과 반복 예약 등록 절차도 포함하며, 실제 예약·지속 실행 검증은 남아 있습니다.
- **URL 분석기:** 판매처 정보 수집, 이미지·검색 기반 포장 추정, 공개 세율 기반 예상 세금 계산을 수행합니다. NestJS·PostgreSQL·별도 워커로 구성했습니다.

두 도구는 현재 독립적으로 동작합니다.

## 대화로 진행한 구매·배송신청

**첫 요청1회와 후속 응답6회, 사용자 메시지 총7회**로 주문 대조와 배송대행 접수까지 진행했습니다. 후속 응답은 로그인 완료2회, 입력·제출 승인2회, 구매·인증 완료 알림2회였습니다. 상품·배송지 확인과 주문 정보 입력·접수 대조는 에이전트가 수행했습니다.

로그인·직접 구매·통관 인증의 화면 조작 횟수는 별도로 측정하지 않았습니다. 기존 계정·저장 정보가 있는 단일 사례이며 [메시지 집계 기준](interaction-count.md)에 범위를 명시했습니다.
